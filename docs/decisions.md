# Ключевые решения

> **MVP.** Решения приняты для быстрого получения работающего прототипа. Там, где это важно, указано, когда их стоит пересмотреть.

## 1. 3D строится кодом по профилю, а не из моделей

- **Выбрано:** параметрическая геометрия по сечению профиля (см. [facade-3d.md](facade-3d.md)).
- **Альтернатива:** моделировать в Blender и экспортировать GLB.
- **Почему:** у разработчика нет опыта в 3D и нет 3D-художника; готовая модель при смене размеров растягивается и искажает рельеф; у заказчика уже есть чертежи сечений; профили можно добавлять данными.
- **Пересмотреть:** если понадобятся детали, которые не описываются сечением (сложная лепнина, нестандартные ручки). Тогда — отдельные GLB.

## 2. Только клиентский 3D, с картинкой до загрузки

- **Выбрано:** `next/dynamic` с `ssr: false` внутри клиентского компонента; рендер по требованию; ограничение `dpr`.
- **Почему:** WebGL не работает на сервере; тяжёлый код 3D не должен тормозить остальной сайт и SEO.
- **Следствие:** в каталоге нет вращающегося 3D в каждой карточке (это слишком тяжело на телефонах). Карточки показывают фото, а вьюер живёт только на странице фасада. С главной 3D убран (ноябрь 2026): hero — фото кухни.

## 3. Примерочная кухни: фото + маски + перекраска (вариант A)

- **Выбрано:** перекраска фото в браузере (см. [kitchen-tryon.md](kitchen-tryon.md)).
- **Альтернативы:**
  - B: 3D-кухня в three.js на нашем генераторе фасадов (честная геометрия, но «стилизованный» вид, а не фото);
  - C: фотореалистичные рендеры от 3D-художника с перекраской (дорого и долго, но лучший результат);
  - D: генерация нейросетью (отвергнута: нет контроля над точностью профиля и цвета, для производителя это риск).
- **Почему A:** заказчик в первую очередь хотел «как в журнале», а не точную геометрию; реализация простая и быстрая; расширение сцены это новое фото плюс разметка.
- **Цена решения:** нельзя менять фрезеровку и покрытие на самом фото. Для каждой фрезеровки нужна отдельная сцена.
- **Пересмотреть:** если заказчик захочет менять фрезеровку на одной сцене, то нужен B (или C для премиальной версии).

## 4. Каталог живёт в коде

- **Выбрано:** `src/lib/catalog.ts`, без CMS.
- **Почему:** в MVP нужно было быстро показать результат; данных 25 позиций.
- **Пересмотреть:** когда заказчик захочет сам править каталог. Подойдёт Payload, Sanity или Strapi; структура `Facade` уже близка к схеме контента.

## 5. Заявки, а не корзина

- **Выбрано:** форма с подстановкой выбранного варианта.
- **Почему:** цена зависит от размеров, цвета и фрезеровки; заказчик продаёт на заказ и уточняет детали по телефону. Это лидогенерация.
- **Следствие:** нет цен и калькулятора. Калькулятор это отдельный этап.

## 6. Дизайн-система из PDF

- **Выбрано:** оттолкнуться от каталога: белая и графитовая палитра, жирный геометрический гротеск (Montserrat), мелкие подписи, диагональный срез как мотив.
- **Почему:** это просили, плюс продукт цветной, поэтому интерфейс нейтральный и не спорит с фасадами.
- **Пересмотреть:** «уникальный дизайн» из задания пока реализован умеренно (на главной: тёплая бежево-коричневая палитра, скруглённые bento-блоки, hero с фото кухни). Возможна более смелая версия: анимации по скроллу, диагональные секции, «разобранный» фасад для страницы покраски.

## 7. Цвет по палитре с приблизительными HEX

- **Выбрано:** 13 популярных RAL и 3 «дерева», HEX приблизительные.
- **Почему:** для превью точность не критична, а физические образцы заказчик показывает отдельно. На сайте стоит соответствующая пометка.
- **Пересмотреть:** при подключении полных палитр (RAL, NCS, Color System) и реальных текстур плёнок.

## 8. Python только для подготовки данных

- **Выбрано:** скрипт масок на OpenCV запускается вручную, результаты (PNG) лежат в репозитории.
- **Почему:** в рантайме Python не нужен, а разметка делается редко.

## Главная в тёплом «bento»-стиле (ноябрь 2026)

- **Решение:** главная переделана по референсу заказчика: кремовый фон, акцент taupe, тёмный cocoa, скруглённые карточки, плавающая шапка-«таблетка», hero-баннер с фото кухни. Токены `cream`, `sand`, `taupe`, `cocoa` в `globals.css`.
- **Почему:** прежний тёмный hero с 3D-вьюером выглядел тяжело и не продавал; 3D нужен в карточке фасада, а не на входе.
- **Распространение:** тот же стиль (скруглённые блоки, pill-кнопки taupe, чипы-фильтры, тёмный cocoa-подвал) применён к каталогу, карточке фасада, примерочной, форме заявки и подвалу. Токены `ink`, `mist`, `night` остались в `globals.css`, но в разметке больше не используются. Фото на главной взяты из сцен примерочной и PDF, прав на публикацию нет (см. [data-and-assets.md](data-and-assets.md)). Цифры в блоке «Фабрика в цифрах» взяты из каталога (гарантия, габариты), других нет.
